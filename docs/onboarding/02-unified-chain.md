# 02. 통합 체인 실행

명령은 `/sboot-rehost:start`.

## 1. 스테이지 지도 도출 (`stage_map.py`)

부트로더 이미지는 여러 스테이지가 이어 붙은 컨테이너다. 평문·암호화·부재가 섞여 있다.

| # | 단계 | 방법 |
|---|---|---|
| 1 | 구간 분류 | 엔트로피 격자로 평문 / 암호화 / 제로 패딩 구분 |
| 2 | 스테이지 경계 | 아키텍처별 리셋 스텁 시그니처 탐색 |
| 3 | 구간 식별 | 문자열 문맥으로 정체 판별 |
| 4 | 적재 주소 | basefind 후 **리터럴 앵커로 교차 검증** |

- **스테이지는 엔트로피 경계에서 쪼갠다.** 스텁-스텁 구간이 평문으로 시작해 암호화로
  이어지면 **두 스테이지**다. 앞은 `exec`, 뒤는 `encrypted`
- 구간 전체의 암호화 비율로 판정하면 실행 가능한 앞부분이 함께 버려진다. Exynos 9820 의
  BL1(20 KB 평문, 진입 스텁 `0x10`)이 EPBL(38 KB 암호화)에 흡수되어 65.5% 가 되고,
  **리셋 PC 가 BL33 으로 밀린다.** 그러면 "첫 스테이지부터 연속 실행"이 성립하지 않는다
- 구간이 암호화로 시작하면 쪼개지 않는다. 진입할 수 없기 때문이다
- **4단계 교차 검증은 생략 불가.** 포인터 포함률만으로 고른 후보는 실측에서 틀렸다
  (약 `0xBE000000` 차이)
- BSS 포인터를 파일 오프셋으로 환산했을 때 **제로 패딩 시작 지점에 착지**해야 확정값
- 앵커 없는 후보는 `confidence: candidate`. 확정값으로 쓰지 않는다

### 리셋 스텁 시그니처 (AArch64)

```
b    .+4
adr  x0, <벡터 테이블>
mrs  x1, currentel
cmp  x1, #8  → msr vbar_el2
cmp  x1, #4  → msr vbar_el1
     그 외   → msr vbar_el3 ; scr_el3 |= 0xf
```

- `mrs xN, currentel` 단독은 조회 함수. **벡터 베이스 기록이 근처에 있어야** 경계다
- AArch32 는 `CurrentEL` 이 없다. 진입은 **GFH 가 선언한 점프 · 페이로드 선두의 벡터 테이블 ·
  crt0** 중 하나에서 찾고, 그 시그니처를 못 찾으면 종료코드 3 → `BLOCKED_ARCH`
- **"스테이지가 없다"가 아니라 "도구가 못 찾았다"** 이며, 이 구분을 흐리면 도구 결손이
  펌웨어 판정으로 둔갑한다
- 아키텍처 자체도 입력이 아니라 도출값이다. `stage_map.py --detect-arch <이미지>` 가 한 줄 JSON
  (`arch` · `entry_signature` · `basis` · `confidence`)을 내고, 구조적 시그니처가 없으면 `unknown` 이라고
  답한다. `start` 가 첫 컨테이너의 답을 `INPUT.md` 에 기록해 넘기고, `unknown` 이면 파이프라인이 다시 묻고,
  그래도 `unknown` 이면 기본값이 아니라 임시로 arm64 를 써 보고 시그니처가 없을 때 근거와 함께 `BLOCKED_ARCH`
  로 선다. 뒤의 이미지는 이미지마다 다시 묻는다 (체인이 ISA 를 섞을 수 있다)
- arm32 의 로드 베이스는 **독립된 앵커 둘이 한 값에 수렴할 때만** 확정한다 (예: 자기 재배치 스텁의
  리터럴과 헤더의 페이로드 크기, 리터럴 풀 포인터의 착지). 수렴하지 않으면 그 스테이지는
  `state: unconfirmed` 로 실행 불가 표시하고 후보와 반려된 앵커를 남긴다 (`BLOCKED_ARCH` 가 아니다)
- 컨테이너 밖 스테이지(매체에서 이전 스테이지가 읽어 적재하는 것)는 `origin: medium` 으로, 진입점이
  이전 스테이지 코드 안에서 정해지는 것(커널)은 `origin: handoff` 로 표현한다

산출: `stage_map.json` 에 스테이지마다
`{name, file_range, state, load_base, entry_pc, evidence}` + 스키마 v2 의
`{arch, origin, entered_by, anchors, confidence, container}`. **감시와 검증은 `entry_pc` 하나를 쓴다.**

## 2. 건너뛰기

실행 불가한 스테이지는 이전 스테이지의 진입을 **다음 실행 가능 스테이지로 재지정**한다.

진입 코드가 **쓰기 전에 읽는 것**을 열거해 분류한다.

| 읽는 대상 | 판정 |
|---|---|
| 하드웨어 레지스터 | 문제없음. 머신이 어차피 모델링한다 |
| 이전 스테이지가 쓴 메모리 | 값 공급이 필요하며, 공급 자체가 우회다 |
| 분류 불가 | **미확정으로 기록.** 레지스터라고 가정하지 않는다 |

## 3. 머신이 제공하는 것

| 항목 | 내용 |
|---|---|
| 리셋 PC | 첫 스테이지 진입점 (도출값) |
| 진입 EL | 스테이지의 진입 스텁이 쓰는 `vbar_el*` 가 정한다 |
| 스테이지 배치 | 컨테이너를 한 번 읽어 스테이지별 적재 주소로 복사 |
| 이전 단계 핸드오프 | 첫 스테이지가 호출하는 함수 포인터 슬롯 |
| 메모리 골격 | DRAM · SRAM · 주변장치 창 |
| UART | 송신 1지점, 수신은 chardev 콜백만 |
| SMC shim | 펌웨어가 실제 발행하는 function id 별 응답 |
| 부팅 매체 | 합성 GPT 디스크 → [03](03-boot-medium.md) |

### 함정

- **진입 PC ≠ 적재 주소.** 파일 오프셋 0 은 컨테이너 헤더다. 도출 실패 시 적재 주소로
  대체하지 말고 빌드 실패로 보고
- **진입 EL 에 기본값을 두지 않는다.** `has_el3=false` 를 기본으로 두면 `vbar_el3` 를
  쓰는 스테이지가 조용히 깨진다. 답은 `stage_map.json` 에 있다
- **머신은 입력을 만들지 않는다.** 입력은 `uart_harness.py` 가 QEMU 외부에서 넣는다

### 핸드오프 슬롯

- 상수 주소를 적재한 뒤 간접 호출하는 지점을 찾는다
- 각 슬롯의 계약은 **호출부의 인자 구성에서** 도출한다. 위치로 추정하지 않는다
- **호출되는 슬롯만** 모델링한다. BootROM 전체 흉내는 필요하지도 가능하지도 않다
- 여기서 채운 슬롯은 전부 우회이며 기록 대상이다

## 4. 인터랙티브 표면

UART 셸 또는 fastboot/USB 이며 **도출값**이다. 표면 칸은 **선택**이다.

- **UART**: 드라이버에 수신 경로(RBR 읽기, rx 폴링)가 있는가
- **USB**: 디스패처가 명령 테이블을 참조하는가
- 테이블이 있어도 순회하는 디스패처가 없으면 도달 불가
- 도출값이 `none` 이면 사다리에서 표면을 빼고 `autoboot` 로 기록한다. 입력 없이 커널까지 가는
  부트로더가 있기 때문이다
- `BLOCKED_NO_INPUT_PATH` 는 **회차가 입력을 기다리며 멈춘 것이 관측됐고** 입력 경로가 없을 때만 선다

### 입력 게이트

- 부팅 중 콘솔을 잠깐 폴링해 **특정 바이트 연속 입력**(대개 CR `0x0d` N회)이면 셸로 간다
- 보통 일회성이라 그 창이 열린 동안 도착해야 한다
- 연타 수와 게이트 주소는 도출값. `input_plan.json` 에 기록
- 도출하지 못하면(`bytes` 와 `count` 가 둘 다 있어야 쓸 수 있다) **패턴을 보내지 않고** `source: "absent"` 로 기록한다.
  기본 연타 수는 없다 (한 부트로더의 게이트를 모든 부트로더에 주게 된다). 프롬프트가 실제로 나오면 명령은 한 번 보낸다
- 표면 칸의 관측 문자열도 도출값이다. shell 표면인데 `milestone_tokens.txt` 가 없으면 내장 배너로 판정하지 않고
  도달로 세지 않으며 `fingerprint.json` 의 `surface_not_credited` 가 이유를 말한다

## 5. 서명 검증

**이미지도 검증 코드도 벤더 것이므로 원래 통과해야 정상이다.** 실패하면 대개 우리가 준
입력이 잘못됐다. (해시를 하드웨어 엔진이 계산하는 펌웨어는 이 전제가 서지 않는다. 아래 참조)

조사 순서. 검증 코드는 가장 마지막에 의심한다.

1. 매체에 그 파티션이 그 이름으로 있는가
2. 읽어온 바이트가 맞는가 (블록 크기·GPT 오프셋 오류는 그럴듯한 쓰레기를 만든다)
3. 롤백 인덱스 읽기가 응답하는가
4. 키 대조 대상이 있는가
5. 그다음에야 연산 경로

**검증을 패치로 무력화하지 않는다.** 정직하게 통과시킬 수 없으면 보고하고 정지한다.

### 해시가 하드웨어 엔진이면

digest 가 SMC → 모니터 → 엔진 레지스터 경로에서 계산되는 펌웨어는 엔진 없이는 모든 digest 가 틀리게
나와 **무패치 통과가 불가능하다.** 먼저 해시가 어디서 계산되는지 도출하고, 하드웨어이면 이 순서로 간다.

1. **엔진을 모델링**해 digest 가 실제로 계산되게 한다 (정직한 길. 실현 가능성은 아직 시험하지 않았다)
2. 안 되면 비교 결과를 바꾸는 패치를 **라벨을 달아** 허용한다. 표지 `F` · 부작용을 채운 우회 기록 ·
   `/* bypass:<id> */` 패치 표 행 · 칸 `reached_bypassed` · 음성 시험
3. 둘 다 안 되면 정지한다

라벨 없는 우회는 어느 경우에도 허용하지 않는다.

## 6. 커널 진입

- 부트로더가 boot image 를 읽고, 검증하고, DTB 를 조립해 점프한다
- 램디스크 크기가 0 이면 **system-as-root**. 스토리지 모델이 동작하기 전에는
  유저스페이스가 존재하지 않는다
- 부트로더의 커널 점프 줄(`kernel_entry`, 도출값)과 커널 배너(`kernel_alive`)는 다르다
